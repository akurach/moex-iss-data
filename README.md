# MOEX ISS Data

Неофициальный skill для AI-агентов и небольшой Python-клиент поверх публичного
[MOEX ISS API](https://iss.moex.com/iss/reference/).

Репозиторий помогает находить инструменты и режимы торгов, получать текущие
рыночные данные, дневную историю и свечи. Он не является продуктом Московской
биржи, торговым терминалом или инвестиционным сервисом.

## Для чего это нужно

ISS возвращает данные в компактных таблицах `columns` и `data`. Этот skill
описывает, как корректно выбрать инструмент и торговый режим, прочитать такие
таблицы, пройти пагинацию и не выдать исторические или задержанные данные за
данные в реальном времени.

В комплекте есть клиент `scripts/iss_get.py`. Он выполняет публичные HTTPS
GET-запросы, превращает строки таблиц в объекты с именованными полями и отдаёт
результат как JSON. Это удобно для агента, скрипта или ручной проверки.

Для финансовой отчётности эмитента, дивидендов и корпоративных действий нужны
отдельные источники. Не следует конструировать непроверенные ISS URL по
аналогии с примерами этого репозитория.

## Возможности клиента

- принимает только путь вида `/iss/...json` и параметры через `--param`;
- делает публичные GET-запросы к `https://iss.moex.com`;
- возвращает строки с именами полей, метаданные, источники запросов и состояние
  пагинации;
- сохраняет URL, время получения в UTC, HTTP-статус и
  `X-MicexPassport-Marker`, если сервер его прислал;
- собирает все страницы выбранного блока через `--all --block NAME`;
- останавливается при повторной странице, изменении общего числа строк или
  преждевременной пустой странице;
- делает один ограниченный повтор при временных ошибках сети, `429` и `500–504`;
- ограничивает объём `--max-pages` (по умолчанию 100).

Клиент не выбирает за пользователя или агента нужную бумагу, режим, сессию или
смысл ценового поля. Он не рассчитывает доходность и денежные показатели, не
записывает CSV и не делает торговых операций.

## Ограничения данных и доступа

Публичный поток в [описании интерфейсов MOEX](https://www.moex.com/a7939)
указан как задержанный на 15 минут. Это не
означает, что любой ресурс, инструмент или поле всегда имеет ровно такую
задержку. У разных ресурсов может быть разный режим доступа; фактическую
свежесть нужно проверять по торговой дате, времени и доступным маркерам ответа.
HTTP 200 сам по себе не доказывает доступ к real-time данным.

Для данных в реальном времени оформляйте [подписку у биржи](https://www.moex.com/ru/orders?realtime).
Для коммерческой обработки, публичного распространения и non-display
использования требуются [применимые договоры и права MOEX](https://www.moex.com/ru/datapolicy).
Подписка на real-time не означает
автоматического разрешения на любое из этих применений.

Встроенный клиент не поддерживает логин, cookie, учётные данные или оформление
подписки. Не передавайте пароли и токены в командной строке, query-параметрах,
логах или отчётах.

## Установка skill

### Одной командой через npx

Для установки в Codex на уровне пользователя:

```bash
npx skills add akurach/moex-iss-data --agent codex --global
```

Готовый установщик [skills](https://github.com/vercel-labs/skills) скачает
репозиторий и установит skill в `~/.agents/skills/moex-iss-data`. Он может
предложить выбор способа установки или подтверждение замены существующей
версии. Для установки только в текущий проект уберите `--global`.

Нужны Node.js 22.20.0 или новее и Git. Для работы Python-клиента также нужен
Python 3.9 или новее. Установщик — отдельный инструмент Vercel Labs;
публиковать собственный npm-пакет для этого skill не требуется.
Условия [LICENSE](LICENSE) применяются при любом способе установки.

Другого поддерживаемого агента можно выбрать вместо `codex`, например
`claude-code` или `cursor`. Путь установки зависит от выбранного агента.

1. Откройте [последний релиз](https://github.com/akurach/moex-iss-data/releases/latest)
   и скачайте ZIP скилла в разделе **Assets**. Первый релиз:
   [moex-iss-data-v0.1.0.zip](https://github.com/akurach/moex-iss-data/releases/download/v0.1.0/moex-iss-data-v0.1.0.zip).
2. Распакуйте архив. Внутри находится готовая папка `moex-iss-data` с
   `SKILL.md`, клиентом, справочниками, лицензией и дисклеймерами.
3. Для клиентов, читающих skills из `~/.agents/skills`, перенесите эту папку
   в `~/.agents/skills/moex-iss-data`. Если папка уже существует, сначала
   сохраните её и свои изменения; не распаковывайте новую версию поверх неё.
4. Откройте новую сессию агента или обновите список skills по правилам клиента.

Пример новой установки на macOS/Linux, если архив сохранён в `Downloads`,
а каталога назначения ещё нет:

```bash
mkdir -p ~/.agents/skills
unzip ~/Downloads/moex-iss-data-v0.1.0.zip -d ~/.agents/skills
```

Вместе с архивом опубликован `SHA256SUMS.txt`. При желании скачайте оба файла
в одну папку и проверьте целостность архива:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

Архив самостоятельный: Git и сторонние Python-пакеты для установки не нужны.
Для запуска клиента требуется Python 3.9 или новее. Ссылки **Source code**,
которые GitHub добавляет автоматически, содержат исходники репозитория;
для готовой установки используйте приложенный ZIP скилла.

## Использование с AI-агентом

В клиенте с поддержкой именованных skills можно написать:

> Используй $moex-iss-data: получи последнюю доступную цену акций Базиса,
> укажи время котировки, режим торгов и задержку данных.

> Используй $moex-iss-data: выгрузи дневную историю SBER за последний месяц.
> Проверь полноту, сохрани результат в CSV и приложи ссылки на источник.

Сам клиент возвращает JSON; преобразование в CSV во втором примере выполняет
агент. Если клиент не поддерживает вызов по имени, укажите ему путь к `SKILL.md`.
Справочники в `references/` агент читает по мере необходимости.

Для текущих торгов ориентируйтесь на `is_primary=1` и `is_traded=1`, если задача
не требует другого режима. Для истории отдельно проверяйте период доступности и
возможную смену режима. Текущий основной режим может не покрывать старые даты.

Не смешивайте `LAST`, `PREVPRICE`, `CLOSE`, `LEGALCLOSEPRICE` и `WAPRICE`:
это разные показатели. `null` означает отсутствие значения, а не ноль.

## Запуск из командной строки

Ниже пути даны относительно корня репозитория. Python 3.9 или новее уже
достаточен: сторонние пакеты не нужны.

Получить спецификацию инструмента:

```bash
python3 scripts/iss_get.py /iss/securities/SBER.json
```

Найти инструменты по названию:

```bash
python3 scripts/iss_get.py /iss/securities.json \
  --param 'q=Сбербанк' --param engine=stock --param market=shares \
  --all --block securities
```

Получить рыночные блоки для известного примера SBER на TQBR:

```bash
python3 scripts/iss_get.py \
  /iss/engines/stock/markets/shares/boards/TQBR/securities/SBER.json \
  --param iss.only=securities,marketdata,dataversion
```

Выгрузить всю историю SBER за фиксированный прошлый период:

```bash
python3 scripts/iss_get.py \
  /iss/history/engines/stock/markets/shares/boards/TQBR/securities/SBER.json \
  --param from=2025-01-01 --param till=2025-12-31 \
  --param tradingsession=3 --all --block history
```

Получить доступные интервалы, а затем дневные свечи BAZA за фиксированный период:

```bash
python3 scripts/iss_get.py \
  /iss/engines/stock/markets/shares/boards/TQBR/securities/BAZA/candleborders.json

python3 scripts/iss_get.py \
  /iss/engines/stock/markets/shares/boards/TQBR/securities/BAZA/candles.json \
  --param from=2026-09-14 --param till=2026-10-13 \
  --param interval=24 --all --block candles
```

SBER, BAZA и TQBR в примерах — не универсальные подстановки. Для другого
инструмента сначала проверьте его спецификацию и режимы. Примеры не содержат и
не подразумевают «текущую цену».

## Полнота и коды выхода

Без `--all` клиент возвращает один HTTP-ответ. Он не заявляет полноту набора.
Для выгрузки всех страниц обязательны одновременно `--all --block NAME`.
Например, для истории это `--all --block history`, для свечей —
`--all --block candles`.

В JSON есть объект `paging`:

- `complete=true` — пагинация выбранного запроса завершилась;
- `complete=false` — достигнут `--max-pages`, результат частичный;
- `requested=false` и `reason=single_response` — получен один ответ;
- `reason` поясняет, почему пагинация остановилась.

Код выхода `0` означает успешное выполнение. Код `3` означает частичный ответ
из-за лимита страниц; такой результат нельзя называть полной выгрузкой. Код `2`
означает ошибку запроса, структуры ответа или аргументов.

`complete=true` подтверждает только завершение страниц выбранного endpoint. Это
не подтверждение экономической полноты истории за пределами указанного режима,
периода и фильтров.

## Формат результата

Клиент нормализует компактную таблицу ISS в массив объектов. Упрощённый пример:

```json
{
  "blocks": {"history": [{"SECID": "SBER", "TRADEDATE": "2025-01-03"}]},
  "metadata": {"history": {}},
  "sources": [{"http_status": 200, "fetched_at_utc": "..."}],
  "paging": {"requested": true, "complete": true, "reason": "cursor_total"}
}
```

Не интерпретируйте `passport_marker=granted` как доказательство real-time для
конкретного поля. Также `denied` при HTTP 200 может сопровождать задержанные
данные. Сверяйте время и правила доступа для нужного ресурса.

## Тесты

Из корня репозитория:

```bash
python3 -B -m unittest discover -s scripts -p 'test_*.py'
```

Набор из 13 тестов покрывает нормализацию строк, пагинацию с
курсором и без него, повтор страниц, изменившийся total, неполный результат,
ошибки структуры и ограниченные повторы временных HTTP-ошибок. В GitHub Actions
эти проверки запускаются на Python 3.9 и 3.14 без обращения к API биржи.

Публичные запросы дополнительно проверены вручную на SBER и BAZA. Это не
подтверждает доступность всех рынков или работу авторизованного доступа.
