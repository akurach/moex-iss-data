# MOEX ISS: получение данных

Работай через публичный HTTPS API `https://iss.moex.com/iss`. Для обычной выгрузки достаточно HTTP GET; MCP и отдельная библиотека не обязательны.

Код и инструкции разрешены только для личного некоммерческого использования: [LICENSE](LICENSE), [условия и дисклеймеры](DISCLAIMER.md). Получение данных не дает права на их коммерческое использование или распространение. Real-time требует соответствующей подписки MOEX; другие цели могут требовать отдельного договора с биржей. Подписка не отменяет ограничение лицензии самого skill. Этот проект не является официальным продуктом MOEX.

## Порядок работы

1. Определи инструмент, тип данных, период, интервал свечей и нужную сессию. Для «сегодня» используй дату пользователя, а в ответе указывай фактическую торговую дату. Уточняй только неоднозначность, которая влияет на результат.
2. Если известен точный SECID, начни с `/iss/securities/{SECID}.json`. Иначе найди кандидатов через `/iss/securities.json?q=...`. Поиск приблизительный и постраничный: первая строка не обязательно нужная бумага. Проверь SECID, ISIN, название и тип; не смешивай обыкновенные и привилегированные акции.
3. Из блока `boards` спецификации возьми `engine`, `market`, `boardid`. Для текущих торгов ориентируйся на `is_primary=1` и `is_traded=1`, если пользователь не указал иной режим. Для истории проверь `history_from/history_till` и смену режимов: сегодняшний основной режим может не покрывать старые даты.
4. Выбери запрос по [справочнику сценариев](references/requests.md). Сначала получи схему; затем сокращай ответ через `iss.only` и `{block}.columns`. Используй обычный JSON с `columns` и `data`, без `iss.json=extended`.
5. Собери все страницы, если нужна полная выборка. Проверяй свежесть, единицы и пропуски по правилам ниже. Для машинной выгрузки используй [Python-клиент](scripts/iss_get.py) либо эквивалентный HTTP-клиент.
6. Отдай данные/файл и кратко сообщи: SECID, режим, период и сессию, выбранное ценовое поле, единицы, время данных, источник и полноту выгрузки. Отдельно обозначь вычисленные показатели.

## Обязательные проверки

- Преобразуй строки как `dict(zip(columns, row))`; не закрепляй позиции полей. Имена и регистр бери из ответа: поиск использует `secid`, рыночные таблицы — `SECID`. Объединяй рыночные строки по `SECID + BOARDID`, а историю также по дате и сессии.
- `null` означает отсутствие значения, не ноль. Пустой блок, отсутствующий блок и HTTP-ошибка — разные результаты. При пустой истории проверь даты доступности, режим и календарь торгов; не создавай фиктивные нулевые строки.
- `marketdata.LAST`, `securities.PREVPRICE`, `history.CLOSE`, `LEGALCLOSEPRICE` и `WAPRICE` — разные показатели. Не подменяй отсутствующий `LAST` другой ценой молча. Для последнего завершенного дня используй историю и назови фактическую дату.
- Вместе с ценой сохраняй валюту, единицу котировки и при необходимости `LOTSIZE`. Для облигаций проверь, является ли цена процентом номинала, а также валюту номинала и НКД. Не умножай объем на размер лота без определения поля в `/columns`.
- Для представления цены учитывай `DECIMALS`; явно заданная `PRECISION` поля имеет приоритет. Сохраняй исходную точность для расчета; для денежных вычислений используй десятичную арифметику.
- HTTP 200 не доказывает актуальность или наличие подписки. Сохраняй `X-MicexPassport-Marker`, дату торгов и доступные `UPDATETIME`, `SYSTIME`, `TIME`. `denied` при HTTP 200 может сопровождать задержанные данные; `granted` сам по себе также не доказывает свежесть конкретного значения. Если задержка не установлена, так и напиши. Не вычисляй ее только из `LAST`: по бумаге могло не быть сделок.
- Не выдавай время сервера без часового пояса за UTC. Времена MOEX интерпретируй в контексте московского рынка (`Europe/Moscow`), проверяя определение поля; UTC-время получения HTTP-ответа храни отдельно.
- Пагинация: `start` начинается с 0; увеличивай на фактически полученное число строк. Используй `{block}.cursor`, если он есть, иначе продолжай до пустого блока. Короткая страница не доказывает конец. Не теряй курсор через `iss.only`. Указывай неполноту при лимите страниц или сбое. Для изменяющегося реестра сделок страницы не гарантируют единый снимок.
- Не складывай строки разных сессий с итоговой сессией повторно. Интервалы свечей получай из `/candleborders`; незакрытая свеча может измениться. Не считай историю автоматически скорректированной на дивиденды, дробления и другие корпоративные действия.

## Запуск клиента

Пути в примерах указаны относительно папки этого skill. Подставь ее абсолютный путь; текущая рабочая папка агента может быть другой.

```bash
python3 scripts/iss_get.py /iss/securities/SBER.json

python3 scripts/iss_get.py \
  /iss/history/engines/stock/markets/shares/boards/TQBR/securities/SBER.json \
  --param from=2025-01-01 --param till=2025-12-31 \
  --param tradingsession=3 --all --block history
```

Клиент выполняет только публичные GET-запросы, возвращает JSON с именованными полями, HTTP-источниками и состоянием пагинации. Он не выбирает инструмент, режим или смысл цены за агента. Для полной выгрузки нужен `--all --block NAME`; без него возвращается только один ответ, полнота не заявляется. `--max-pages` ограничивает объем (по умолчанию 100). Достигнутый лимит дает `complete=false` и код выхода 3; ошибка — код 2. Частичный результат нельзя представлять как полный.

Для доступа по подписке, HTTP-ошибок, точных ссылок на документацию и отличий от PDF читай [доступ и источники](references/access-and-sources.md). Условия из руководства 2016 года не переносить на текущий сервис без проверки. Skill не дает прав на распространение биржевых данных и не выполняет торговые операции.
